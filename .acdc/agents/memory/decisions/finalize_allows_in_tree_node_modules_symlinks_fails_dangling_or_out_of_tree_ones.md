## Compiled Truth

Decision: Allow symlinks under node_modules that resolve inside the app dir. Fail staging on dangling links and on links that resolve outside it.
Why: npm always creates node_modules/.bin/* as symlinks. Out-of-tree workspace or file: links have no target in the droplet.
Rejected: failing on any symlink (the pnpm buildpack rule) because every npm app with a CLI dependency would fail; allowing only .bin links because legitimate in-tree workspace links would fail; warn-only because broken workspace links would deploy and then fail at runtime with "Cannot find module". For the scan scope (only node_modules paths, links not followed; limit stated in lib/utils.sh find_bad_symlinks): rejected checking every symlink in the app dir because stray broken links in src/ or docs/ that the app never loads would fail staging; rejected following links with a visited set because it costs about 15 more lines of bash for a layout npm ci and npm workspaces never create.
Revisit when: npm changes how it lays out .bin or workspace links, or a real app ships a node_modules link into a folder outside node_modules paths.
